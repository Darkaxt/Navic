## Evidence-derived contracts

### EF-C1 — Three independent pieces of presentation truth

A result can have the right page/layout and still have unacknowledged visual content or old decoration pixels. Preserve the existing exact session/publication/binding/material/registration checks. At materialization, associate the applicable accepted highlight request/state with the generated material; at actual display, verify that association or report it as superseded/pending. Do not infer it from a mutable painter reference, a successful bitmap allocation, or the current global highlight fields.

Use existing provenance/request/generation types first. A minimal immutable decoration stamp, if a real representational gap is proven, is metadata subordinate to the existing coordinator and display binding, never another authority, operation, registry, or controller. Capture/equality checks stay in memory; diagnostics contain only fixed labels, counts, states and booleans.

### EF-C2 — Readable predecessor survives preparation

After an authentic readable page/spread is committed, optional adjacent-page preparation or highlight refresh cannot independently revoke it. A successor is published only with matching semantic/layout, material and physical presentation evidence and the existing owner/input acknowledgement. Cancel preserves the source; failed preparation leaves an honest usable source or explicit terminal error under the governing operation contract.

Neutral has no predecessor. Do not invent a blank/native/legacy page to satisfy this rule during initial bootstrap.

### EF-C3 — Atomic spread result, real next-turn admission

One completed turn advances the spread once. A cancelled turn does not advance it. Settlement and owner/input publication must finish through the existing typed fact/command path. The next admitted turn must actually run; an idle flag without queue progress is not acceptance. Neither a method return nor Google's visibility restoration is a substitute for Navic's matching display proof.

### EF-C4 — Latest-applicable decoration, without a moving-target commit barrier

Page/spread correctness remains a hard commit condition. Continuously advancing audio must not force every turn to wait for all future highlight updates. Capture the applicable state for each actual materialization, reject obsolete session/layout/range results, coalesce superseded decoration work only within the same valid display context, and publish equal-or-newer applicable state without regressing.

Retain one legal existing publication/wake route. Continuous queued input may not postpone all decoration publication until the queue becomes empty. Establish deterministic progress at legal publication opportunities and measure runtime catch-up latency. Do not invent a numerical freshness guarantee from Google's 34 ms scheduler or rolling 500 ms gate. Do not add a callback-local timer, hidden polling loop, or Task 6 coordinator clock.

### EF-C5 — Layout is not raster pixel acknowledgement

Passive layout/page metadata authorizes the intended capture geometry, not by itself the rendered pixels. Keep Navic's existing passive renderer readiness/capture contract and actual renderer/deck/display witnesses. The absence of an offscreen visual-state callback in the inspected Google path is not permission to remove Navic's proof.

### EF-C6 — Honest disposal and recovery

Close/disposal retires the session and makes late callbacks release-only or inert as required by exact resource custody; it is not a successful turn. Missing completion, rejected publication, renderer failure and unavailable material need named bounded outcomes using the current authorized timer/error routes. Surface recreation must not commit an unacknowledged destination. If the fresh-session path lacks a lawful timer owner, that is a feasibility blocker, not permission to activate a no-op clock or start Task 7.
